# 14 - Always-on backend (single Fargate task)

Replace Lambda + API Gateway with one always-on ECS Fargate task behind an ALB: ARM64, 0.25 vCPU / 0.5 GB, `desired_count = 1`, no autoscaling.

Steps:

1. Package the existing non-lambda `serve()` build (`main.rs`, `#[cfg(not(feature = "lambda"))]`) as a Docker image instead of a lambda zip. Add `GET /health` for the ALB target group check.
2. `infra/main.tf`: drop `aws_lambda_function.api` and `aws_apigatewayv2_*`. Add: ECR repo, ECS cluster + task definition (same env vars the Lambda gets today, plus `PORT`), ECS service, task IAM role reusing the existing `api_dsql`/`api_chime`/`api_media`/`api_messenger_management`/`api_read_jwt_secret` policies, ALB + target group, security group allowing inbound from the ALB only.
3. Put the task in a public subnet behind the ALB (no NAT) unless the Lambda is already in a VPC.
4. `backend/Makefile`: `make deploy [stage]` builds the image, pushes to ECR, `aws ecs update-service --force-new-deployment`.
5. After verifying in `dev`: delete the Lambda role/function, API Gateway resources, `infra/placeholder/`, and the `lambda` cargo feature.

## User position: memory-backed, DB on logout/redeploy only

Keep `map_positions`, but stop hitting it on every move. Add `Mutex<HashMap<(org_id, user_id), Position>>` in shared state, passed to `features::map::register`, as the thing every route actually reads/writes during runtime.

- At startup, hydrate the map from `map_positions` (one `SELECT` for the whole table).
- `positions_route` reads the map, defaults to `(0, 0, false)` for anyone missing.
- `set_position`/`set_map_active` write the map directly only -- no DB call, no `retry_on_conflict`.
- On `CONNECTION`/`DISCONNECTED` (logout/tab close), flush that user's current entry to `map_positions` before clearing `map_active` -- same place `clear_all_map_active` already hooks in.
- On graceful shutdown (SIGTERM, e.g. `tokio::signal::ctrl_c` / a shutdown future ahead of `axum::serve`'s `with_graceful_shutdown`), flush every entry in the map to `map_positions` before the process exits, so a redeploy doesn't lose live positions.

Project should still work on local and remote.
