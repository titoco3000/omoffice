# 14.7

Lets implement the meetings system.

How it works:

In a meeting panel of the frontend, user A creates a meeting. 
in the backend, a meeting is created, but no room is asigned to it.
In the frontend, it appears to the user that he is connected.
Every user in the org has a list of current meetings; their lists are updated via a channel.

User B clicks on the meeting in the list. Because it isnt invite-only, he is allowed to join.
Now that there are two users in the meeting, a room is asigned to it and both users receive it via a channel.
Both users are connected to it.

User A leaves the meeting. It doenst end, but the room is cleared and user B is diconnected from chime but not from the meeting.
User C joins, a new room is requested. Maybe the same one is asigned, maybe other. 
Same as before: frontends receive chime, connect.

If all users leave the meeting, it is terminated.
If a user is left alone in a meeting for over N seconds (20 for now) it is terminated. 
For that, add an 'idle_since' field to meeting. users cant join meetings idle over N seconds, and dont see it in their frontends.

When the system tries to asign a room to a meeting, it need to check if the chime meeting is still accessible.
