# 13 - office map

## Preparation

Add a "graphics mode" setting to /profile, with the options "map" or "no-graphics".
If on mode "map", the contents of /in should be replaced by a canvas filling the available space and the OrgOnlineView should be rendered on the sidebar in desktop, and via a toggle on the botton right on mobile.



Lets implement a map system. 

How it works:

Every user gets an X and Y coordinate and a map_active in their org participation.
In the frontend, a grid of size OFFICE_SIZE x OFFICE_SIZE (lets say 100 for now) is rendered using a canvas, and each user that is online appears on their cell as an avatar.

If multiple users are on the same cell, they are each rendered with a small offset from the center of the cell.

Users are allowed to move to different cells by either navigating with the arrow keys or clicking on a cell.
There is a fixed time that users are allowed to change their cells: 1 / USER_SPEED. If the user holds an arrow key, it moves them by one cell and starts a timer to allow moving again. On timer end, if the arrow is still clicked, it repeats the process. Mouse clicks during the cooldown are stored and only apply after the cooldown. Multiple clicks during the cooldown override each other, with only the last one beeing applied.

When a user changes cell the event is sent to all online users that have map_active set to true. Their avatar is translated at a fixed speed to the target cell.

The user position is bound from 0 to OFFICE_SIZE - 1
