# 11 - messager rework

Lets rework the messaging system, used by chat and invites. How it should work:

Both the invites and the chat should have no idea they are handling with websocket, or any of the low-level details.

messager show expose a very simplified interface, something like this:

Rust:

messager.send(
    message=some_json_content,
    channel="somechannel",
    via=[websocket, email],
    to=[userA, userB]
)

messager.send_to_users_on_meeting(
    message=some_json_content,
    channel="chat",
    via=[websocket],
    meeting=meetingID
)

messager.send_to_users_on_org(
    message=some_json_content,
    channel="other-channel",
    via=[websocket],
    org=orgID
)

messager.on_message("chat", |msg, origin|{println("got msg: {msg} from user {origin}")})

JS:
messager.send(
    message=some_json_content,
    channel="chat"
)

messager.on_message("chat", (msg)=>console.log(`got msg: ${msg} from backend`))

Lets replace the connections table with something like active_users. It will include their current meeting (nullable).
