# 7 - Role-Based Access Controller

### Prompt

This project includes a well-modularized backend, with an API and clean database access.

We want to upgrade it by creating a project-agnostic Role-Based Access Controller - RBAC.

Project-agnostic in here means the RBAC ignores this is a meetings app. The meetings module may use the RBAC.

The basic building blocks are 

- Users
- Organizations
- Roles

A user may belong to 0 or multiple Organizations, and have multiple roles in each (user-org-role table).

Roles are a static project-specific list, except for the roles ["admin", "billing", "team-management"] that are native to the RBAC.

In the backend, there needs to be some way of verifying if the requesting user has a certain role before proceeding with their requisition (ex: "team-management" before inviting a new user to an org, "post" before doing the sample post).

In the frontend there needs to be a similar tool (ex: "team-management" required for displaying the UI to invite a new user to an org")

Any user may create an org and type emails to invite.

There needs to be mechanisms to create orgs, add user, change user role, leave org, delete org.

The last admin of an org is not allowed to leave it.
.
Create a proper login system for the frontend, using the JWT.
