# 13 - Meetings optimization

Lets optimize how meetings are handled. We want our own meeting ID - chime meeting ID is hidden from end user.

Example flow:

User A from org org1 tries to start a meeting with user B.

System creates a new meeting ("our-id-1") belonging to org1 and asigns it the chime-generated id "chime-1".

In the middle of the meeting user B looses power. User A disconnects locally.

The chime meeting "chime-1" becomes empty.

User C from org org2 tries to start a meeting with user D.

System creates a new meeting ("our-id-2") belonging to org2 and asigns it the chime-generated id "chime-1".

User B is back and tries to open the link to our-id-1.

System sees there are no chime available in the pool and creates a new one before asigning it to "our-id-1".

Chime are added to the pool with a min expiry date (4min from abandonment) and max expiry date (12h from creation). 
When the system is looking for meetings in the pool, it removes expired meetings.
