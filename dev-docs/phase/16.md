## 2. Renames

- `GraphicsContext` -> `MapModeContext`, `GraphicsProvider` -> `MapModeProvider`, `useGraphics` -> `useMapMode`, `GraphicsToggle` -> `MapModeToggle`. It picks the `/in` layout (map canvas vs. plain roster); it has nothing to do with theme.
- Keep the localStorage key `omoffice_graphics_mode` and the mode values `"map"`/`"no-graphics"`, so users' saved choice survives.
- Update the module doc comment to match.

## 3. Import rules

- `core/` imports only `core/`.
- `features/X` imports `core/` and other features only through `features/Y/index.js`. No deep imports into another feature. Inside one feature, use relative imports.
- `pages/` imports `core/` and feature `index.js` files.
- Only `app/` imports `pages/`.
- Each feature's `index.js` re-exports only what's used outside the feature.
- Enforce these with ESLint `no-restricted-imports` patterns in `frontend/eslint.config.js`.

## 4. Break the org <-> meetings cycle

`OrgSessionContext` calls `useMeetingSession`, and `MeetingDock` consumes `OrgSessionContext`.

- Add `features/meetings/MeetingSessionContext.jsx`: a provider that calls `useMeetingSession(token, orgId)` and a `useMeetingSessionContext()` hook.
- Remove the meeting session from `OrgSessionContext`, so it only carries the current org and its roster.
- In `App.jsx`, nest `MeetingSessionProvider` inside `OrgSessionProvider`.
- Point every consumer of the meeting-session fields at the new hook.
- Result: meetings -> org and map -> org, with nothing pointing back.
