# 25 - Region sync

Map moves currently go to every org member (`/map/{org}/*`), so AppSync cost per user grows linearly with org size. Deliver moves by region instead, and cut the publish rate. Target: map cost per user stays under ~$1 up to 250 members.

## Constants

- Backend `features/map/mod.rs`: `REGION_SIZE: i32 = 10` (cells), `pub fn region_of(x, y) -> (i32, i32)` = `(x / REGION_SIZE, y / REGION_SIZE)`, `REGIONS_PER_SIDE = OFFICE_SIZE / REGION_SIZE`.
- Frontend `features/map/regions.js` (new, pure): same `REGION_SIZE`, `regionOf(x, y)`, `regionKey(rx, ry)` = `"{rx}-{ry}"`, `regionsInRect({minX, maxX, minY, maxY})`.
- Publish rates: `FINE_PUBLISH_MS = 500` (2/s), `COARSE_PUBLISH_MS = 5000` (0.2/s).
- `COARSE_ABOVE_REGIONS = 16`: a viewport touching more regions than this uses the coarse channel.

## Channels

- Fine: `/map/{org}/{rx}-{ry}/{user}`. Published by the user while their cell is in that region.
- Coarse: `/map/{org}/c/{user}`. Published by every moving user, throttled to `COARSE_PUBLISH_MS`.
- The `map` namespace `onPublish` handler in `infra/map_events.tf` is unchanged (it already stamps the last path segment as `user_id`).

## Backend: `features/map/realtime.rs`

1. Update `authorize`:
   - `EVENT_SUBSCRIBE`: `/map/{org}/{region}/*` where `org` is the token's org and `region` is `c` or a valid `{rx}-{ry}` (both integers in `0..REGIONS_PER_SIDE`).
   - `EVENT_PUBLISH`: `/map/{org}/{region}/{sub}` with the same region rule and `sub` equal to the token's subject.
   - Deny the old 3-segment forms.
2. Rewrite the module doc for the new channel layout.
3. Replace the authorize tests: own fine and coarse channel publish allowed; another user's channel, another org, malformed or out-of-range region (`10-0`, `-1-0`, `a-b`, `1-2-3`), old 3-segment channels all denied; subscribe to `/map/org/{region}/*` and `/map/org/c/*` allowed; `/map/org/*` and `/map/*` denied.
4. Unit test for `region_of` (edges: 9 and 10, 99).

## Frontend: `features/map/realtime.js`

1. `openMapEvents` no longer subscribes at connect. Add `setSubscriptions(channels)` on the returned handle: diff against the current set, send `subscribe` for new channels (own subscription id each, map id -> channel) and `unsubscribe` for dropped ones. Remember the desired set so a replacement connection (token refresh) subscribes to it on `connection_ack`; `onReady` fires once the whole desired set is subscribed.
2. `publish(x, y, facing)` chooses the channel from the cell: fine channel for `regionOf(x, y)`, coarse channel on its own slower timer.
   - Fine: send at most one per `FINE_PUBLISH_MS`, latest wins, flushed by a timer so the final cell of a walk always goes out.
   - On a region change, also publish the new cell once to the old region's fine channel, so viewers still on the old region don't keep a stale cell.
   - Coarse: same latest-wins throttle at `COARSE_PUBLISH_MS`.
3. `publishMapMove` (HTTP, for tabs without a map): publish to the fine channel of the cell and to the coarse channel.
4. `onMove` keeps its signature.

## Frontend: `features/map/useMapSession.js` and `MapCanvas.jsx`

1. `MapCanvas` reports its visible rect in cells (`{minX, maxX, minY, maxY}`) to `useMapSession` whenever the set of touched regions changes (not every frame).
2. `useMapSession` computes the wanted channels and calls `mapEvents.setSubscriptions`:
   - always the 3x3 regions around the user's own cell (proximity depends on it);
   - plus `regionsInRect(viewport)` padded by 1 cell;
   - if that touches more than `COARSE_ABOVE_REGIONS` regions, replace the fine channels with `/map/{org}/c/*` (keep the own-region 3x3).
3. When a fine or coarse subscription is newly added, refetch `listMapPositions` and apply it as the base to anyone whose override is older than the fetch start. Give each override an `at` timestamp in `receiveMove`; stop applying stale overrides over fresher fetched positions.
4. Check remote avatars in `MapCanvas` glide across the 2-3 cell jumps the lower rate produces without clipping through walls visually (`navigation.js` route, or straight ease if cheaper).
5. Update the module docs of `useMapSession.js` and `realtime.js`.
6. Local run (no AppSync endpoint) keeps the messenger fallback, unchanged.
